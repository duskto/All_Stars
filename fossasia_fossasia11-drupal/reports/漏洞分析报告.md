# Drupal 6.28 漏洞分析报告（前认证RCE / 认证绕过后RCE）

## 1. 结论先行

### 1.1 前认证RCE
- **直接前认证RCE（未登录即直达 exec/eval sink）**：**未确认**。
- **前认证组合链RCE（前台原语 -> 认证绕过 -> 认证后RCE）**：**确认可行（默认配置）**。

### 1.2 认证绕过后RCE
- **确认可行**：`备份泄露 -> user/reset token伪造 -> 管理员会话 -> PHP filter 执行`。

---

## 2. 默认配置基线（本报告判定依据）

### 2.1 安装状态/入口状态
- `sites/default/settings.php:104`：`$update_free_access = FALSE;`（update.php 默认未开放匿名升级）。
- `install.php` 安装状态门：
  - `install.php:75-79` + `install.php:633-638` 已安装直接退出（`Drupal already installed`）。

### 2.2 运行时关键变量（来自 `fossasia11.sql.recovered`）
- `file_downloads = 1`（public 模式）。
- `file_directory_path = sites/default/files`。
- `clean_url = 1`。
- `filter_formats`：`PHP code` 仅角色 `,4,`（admin）。
- 角色映射：`rid=1 anonymous`, `rid=2 authenticated`, `rid=4 admin`。
- 权限：匿名含 `access content`, `view uploaded files`, `access user profiles`, `access all views`。

### 2.3 暴露面
- 前台未认证/匿名可达路由共 **41** 条（见 `attack-surface.md` 全量表）。

## 3. 已确认利用链（重点）

## 3.1 Step-A：前台信息泄露原语（备份文件）

### 根因位置
- 文件：`./.htaccess`
- 代码段：`line 6`
```apache
<FilesMatch "\.(engine|inc|info|install|make|module|profile|test|po|sh|.*sql|theme|tpl(\.php)?|xtmpl|svn-base)$|...">
```

### 漏洞机理
- 该规则锚定 `$`，匹配“**最后扩展名**”结尾。
- `fossasia11.sql.gz` 最后扩展名是 `.gz`，**不匹配** `.*sql$`。
- 项目根目录存在真实文件：`fossasia11.sql.gz`。

### 结果
- 匿名可下载数据库转储，泄露：
  - `users.pass`（MD5形式密码字段）
  - `users.login`（最后登录时间）
  - `users_roles`（管理员映射，如 uid=1 -> rid=4）

---

## 3.2 Step-B：认证绕过（伪造一次性登录 token）

### 路由与函数
1. 路由注册（匿名可达）：
- 文件：`modules/user/user.module`
- 函数：`user_menu()`
- 代码段：`line 957-964`
```php
$items['user/reset/%/%/%'] = array(
  'page callback' => 'drupal_get_form',
  'page arguments' => array('user_pass_reset', 2, 3, 4),
  'access callback' => TRUE,
);
```

2. token 校验：
- 文件：`modules/user/user.pages.inc`
- 函数：`user_pass_reset()`
- 代码段：`line 109`
```php
$hashed_pass == user_pass_rehash($account->pass, $timestamp, $account->login)
```

3. token 计算公式：
- 文件：`modules/user/user.module`
- 函数：`user_pass_rehash()`
- 代码段：`line 1489-1490`
```php
return md5($timestamp . $password . $login);
```

### 绕过逻辑
- Step-A 已泄露 `$password`(users.pass) + `$login`(users.login)。
- 攻击者可本地计算任意当前时间戳对应 token。
- 访问：`/user/reset/<uid>/<timestamp>/<token>/login`。

### 会话建立证据
- 文件：`modules/user/user.pages.inc`
- 函数：`user_pass_reset()`
- 代码段：`line 111-119`（action=login分支）
- 调用 `user_authenticate_finalize()` 完成登录。

## 3.3 Step-C：认证后RCE（PHP Filter）

### 入口与权限门
1. 内容编辑时可选输入格式：
- 文件：`modules/node/node.pages.inc`
- 函数：`node_body_field()`
- 代码段：`line 300`
```php
$form['format'] = filter_form($node->format);
```

2. `PHP code` 格式绑定 admin 角色：
- 证据：`fossasia11.sql.recovered` 中 `filter_formats` 行：
  - `(4, 'PHP code', ',4,', 0)`。

### 执行链（source->sink）
1. 渲染调用：
- 文件：`modules/node/node.module`
- 函数：`node_prepare()`
- 代码段：`line 1058`
```php
$node->body = check_markup($node->body, $node->format, FALSE);
```

2. 过滤器调度：
- 文件：`modules/filter/filter.module`
- 函数：`check_markup()`
- 代码段：`line 455`
```php
$text = module_invoke($filter->module, 'filter', 'process', ...);
```

3. PHP filter：
- 文件：`modules/php/php.module`
- 函数：`php_filter()`
- 代码段：`line 81`
```php
return drupal_eval($text);
```

4. 最终执行 sink：
- 文件：`includes/common.inc`
- 函数：`drupal_eval()`
- 代码段：`line 1741`
```php
print eval('?>'. $code);
```

### 结论
- 认证后（admin）可达确定性 eval sink，形成 RCE。

## 4. 直接前认证RCE为何未成立（重点排除）

### 4.1 `panels/ajax`
- 函数：`panels_ajax_router()`（`sites/all/modules/panels/panels.module:1193+`）
- 关键门：`panels_edit_cache_get($cache_key)` 为空即拒绝（line 1216-1219）。
- 下游 `ctools_object_cache_get()` 使用 `sid=session_id()` 绑定（`sites/all/modules/ctools/includes/object-cache.inc:37`）。
- 结论：匿名跨会话构造执行链不可达，排除 direct pre-auth RCE。

### 4.2 `views/ajax`
- 函数：`views_ajax()`（`sites/all/modules/views/includes/ajax.inc:15+`）
- 关键门：`$view->access($display_id)` + `$view->validate()`（line 38, 52）。
- 未发现可控 `eval/system/unserialize` sink。

### 4.3 `system/files`
- 函数：`file_download()`（`includes/file.inc:943+`）
- 路径限制：`file_create_path()` + `file_check_location()`（`includes/file.inc:101,229`）。
- 授权限制：`upload_file_download()` 要求 `view uploaded files` 且 `node_access('view')`（`modules/upload/upload.module:156`）。
- 非任意路径读/执行。

### 4.4 `wysiwyg/%`
- 函数：`wysiwyg_dialog()`（`sites/all/modules/wysiwyg/wysiwyg.dialog.inc:11+`）
- 先校验 plugin 是否在 `wysiwyg_get_all_plugins()` 白名单，再调用 `<plugin>_wysiwyg_dialog`。
- 非用户可控 include/eval。

## 5. 过滤与绕过分析（含在线方法对照）

## 5.1 本项目已存在过滤

### A) 文件访问过滤（根目录）
- `./.htaccess` 的 `<FilesMatch>` 拦截若干敏感后缀。
- **缺陷**：未覆盖多后缀 `*.sql.gz`。

### B) 上传过滤（Drupal core）
- `file_munge_filename()`：
  - 去除 null byte（`includes/file.inc:444-445`）
  - 中间可疑扩展加下划线（`line 460-462`）
- `file_validate_extensions()`：后缀白名单正则，锚定到结尾（`line 727-729`）
- 可执行后缀强制改名 `.txt`（`line 643-650`）
- `sites/default/files/.htaccess`：
  - `SetHandler Drupal_Security_Do_Not_Remove_See_SA_2006_006`（阻止目录内脚本直执）

### C) reset token 过滤
- 时间窗 + login 时间约束 + token 公式校验（`user_pass_reset()`）。
- 但当 DB 泄露时可被跨过。

## 5.2 常见绕过方法（线上资料）与本项目落地性

1. 双扩展、大小写、MIME 伪造、polyglot、历史 `%00` 截断等（通用上传绕过）
- 在本项目默认配置下：
  - null byte 被剔除；
  - 后缀校验锚定且可执行后缀被重命名；
  - 上传目录 SetHandler 禁执行。
- **结论**：默认配置下，上传绕过直达 webshell **不优先**。

2. 服务器规则遗漏（扩展保护缺口）
- 本项目真实可利用点即此类：`.*sql$` 未覆盖 `.sql.gz`。
- **结论**：该绕过是当前链路最短、最稳定入口。

## 6. 默认配置可触发性判定

- 在“Apache + `.htaccess` 生效 + 站点根目录直接对外 + 存在 `fossasia11.sql.gz`”条件下：
  - **可触发**（确认）。
- 在以下场景会失效或降级：
  - 根目录无备份文件；
  - Web 服务器额外 deny `*.sql.gz`；
  - 非 Apache 且未迁移等价规则；
  - `PHP code` format 未授权 admin（与当前 dump 不符）。

## 8. 风险评级

- **最终评级：高危（组合链RCE）**
- 原因：匿名入口 + 认证绕过 + 明确 eval sink + 利用链短。

---

## 9. 修复建议（最小变更优先）

1. 立即删除 Web 根目录备份文件；备份迁移到 Web Root 外。
2. 强化根 `.htaccess`：显式拦截 `\.sql(\..+)?$`、`\.bak(\..+)?$`、`\.gz$`（按备份策略）。
3. 禁用 PHP Filter 模块（生产环境建议彻底禁用）。
4. 升级密码存储算法（迁移到现代哈希），避免历史 MD5 账户口令风险。
5. 对 `user/reset` 增加二次验证（IP/UA绑定、一次性 nonce 更强约束、短时单次签发）。
